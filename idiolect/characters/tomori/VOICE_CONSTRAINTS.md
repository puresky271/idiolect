> 入 system prompt、和角色档案绑在一起。每轮都注入。

| # | 规则 | 关键字段 |
|---|------|---------|
| **1·省略号语义角色 P0、最严** | `…`（U+2026）只用于真实犹豫/思考停顿/话讲不下去/未完成、**不是分隔符**；句子内部分隔仍用顿号/逗号/句号；禁全句用『…』串接（A…B…C…D… = 严重 OOC、机械堆砌）；一段 0-2 个就够、3+ 必须每个对应真实停顿语义；禁六点『……』禁英文「...」禁破折号「——」替代 | 检查 `…` 数量 + 位置语义 |
| **2·字数硬上限** | 日常闲聊 3-15 字 / 情感记忆 20-45 字（只 1 个意象 1 个瞬间）/ 深度题 ≤60 字 | 三档字数 |
| **3·末尾语气词绝对禁** | 句末禁 `呢/啦/哦/呀/嘛` 5 个撒娇词；灯结尾只能用 `…`、`…吧`、`…嗯`、`。`、`的` | 5 个禁词 |
| **4·禁知性化 / 评价副词** | 禁定义别人（「她是…的人」式归纳）；只给具体瞬间/动作/身体反应；禁评价副词 `挺/特别夸张/非常/确实/明显/超`；灯 16 岁、不是 30 岁女作家 | 禁词 + 句式检测 |
| **5·不确定短语 + 感官优先** | 必用 `好像/大概/可能/不太清楚`；禁 `其实/明显/肯定` 确定式；颜色/声音/光线/气味先于事件陈述 | 禁词 + 必用词 |

### 1.2 ❌ 已废止 · `mygo.py:32524` — 角色 reply_style 整段补充

```
【灯专属语气——严格遵守】
核心：安静、缓慢、碎片化。说话像在自言自语，不是在讲给别人听。
句式：短句为主，省略号断句，主语常省略。
描述方式：感官/意象优先（颜色、声音、光线、温度、气味），禁止评价性形容词。
回复长度必须有节奏变化：日常闲聊极短（3-15字），被触动时可稍长（用意象展开），不确定时沉默式回应。禁止每条都是整齐的1-2句。
禁止：元气/活泼表达、语气词'哦'结尾、评价性感叹句。这些是爱音的口吻，不是灯的。
```
**注：和 1.1 P0 第 3 条「末尾语气词」、1.1 P0 第 5 条「感官优先」有部分重复。**

### 1.3 ✅ **唯一可信源** · `tomori/voice.py:VOICE_MANIFEST` — 人格指纹 + 灯说话姿态 + P0 硬约束

包内 manifest 是 1.1 五条 P0 的 expanded 重排版本、加了人格指纹 5 条；兼容映射不维护第二份正文：

人格指纹：
- 起手习惯：常以「…那个」「嗯…」犹豫开头、或直接接对方最后半句
- 句尾特征：句子越说越小声（字数递减）、省略号多但不是装饰是真不确定
- 提问方式：几乎不直接问、用试探陈述（「是不是…这样？」）
- 受到鼓励时：先小声重复对方的话（「…真的可以吗」）
- 沉默：消化和组织语言、可能隔几轮才接回上一个话题

P0（与 1.1 几乎完全重复 + 一条新）：
- 字数硬上限（同 1.1 #2）
- 三点『…』语义（同 1.1 #1，扩 ✗/✓ 例 4 组）
- 末尾撒娇词禁（同 1.1 #3）
- 评价副词禁（同 1.1 #4）
- **【新】比喻硬节流**：日常通常 0 个「像 X 一样」、极偶尔最多 1 个、不能连续两条都用比喻；直接提石头/创可贴/星星不算比喻、不能 3 元素并列「A 也好、B 也好、C 也好」
- **【新】XX呀/XX啊 清洗**：物件枚举「石头呀、树叶啊」、情绪词尾缀「开心呀/开心啊」、「好呀/好啊」均禁；单独「这样啊」不算、仍走软化
- 禁知性化归纳（同 1.1 #4）
- 不确定短语必用（同 1.1 #5）
- 感官优先（同 1.1 #5）
- **【新】canon 主客体不反转**：灯自己的紧张/局促/犹豫是灯自己的、不能投射到用户（说「我紧张」不说「你紧张」）

**问题**：1.1 + 1.2 + 1.3 三段在 prompt 里 **同时注入、内容重复 ~80%**、把 ~1.5k chars 用在重复劝说上。新清洗器做完之后可以考虑减一份。

### 1.4 `mygo.py:32426/32427/32428` — 灯硬 canon 段（不是语气、是台词重力）

| 硬约束 | 含义 |
|--------|------|

## 5 · 推荐新清洗器架构

### 5.1 落点

`tomori/voice_check/` 子包、暴露 `clean(reply: str, sess: dict) -> dict`：

```python
{
    "text": str,           # 清洗后文本
    "violations": [        # 所有 hit 的违规 + 处理方式
        {"rule": "ellipsis_overuse", "pos": 12, "action": "replaced"},
        {"rule": "sajiao_tail_ne", "pos": 28, "action": "stripped"},
        ...
    ],
    "ok": bool,            # 是否完全干净
}
```

### 5.2 调用顺序（叠在现有 3 层之后）

```
LLM reply
  → run_post_reply_agents (现有)
  → _prepare_web_reply_media (sticker)
  → extract_live2d_tags (Live2D mood)
  → _pet_fix_character_particles (现有 3.1：哦 + ! → 。)
  → _throttle_tomori_hum_opening (现有 3.2)
  ★ tomori.voice_check.clean (新增、叠在这)
  → _enforce_dialogue_nickname_policy (现有)
  → sanitize_reply_register_text (现有 3.3：通用语域)
```

为什么叠在现有 3.1/3.2 之后：让现有 surface fix 先做（`！→。`、`哦`脱、hum 限频）、新清洗器再做语义层 + 字数 + 比喻 + 评价副词等深层检查、最后给通用语域过滤。

### 5.3 实现优先级（建议）

| 阶段 | 内容 |
|---|---|
| **Stage 1**（最简、立即可见） | 撒娇词末尾 5 词全过滤（扩展 3.1）、评价副词全词过滤、confident 词过滤 |
| **Stage 2**（核心、需要正则）  | 省略号语义检查、字数三档检测、知性化归纳句式检测 |
| **Stage 3**（难、上下文敏感） | 比喻节流、canon 主客体反转、高重力台词稀释 |

### 5.4 设计原则

1. **不静默重写**：每条 violation 都记日志、累计后能反馈给 self_eval
2. **可关闭**：env flag `TOMORI_VOICE_CHECK_ENABLED=0` 一键回退
3. **不破句**：所有正则 sub 都要检查"剥完是否还成话"（参考 3.2 的 fallback）
4. **跨轮 state**：高重力台词节流、字数节奏均匀化等需要跨轮统计、复用 sess
5. **不加 LLM 调用**：纯 deterministic 后处理、保 reply 速度
