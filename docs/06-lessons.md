# 踩坑清单：每条约束是被什么教出来的

> 讲什么：踩坑清单，A–F 六组，每条是「症状 → 原因 → 约束」。约束不是原则宣言，是出过事故之后写下的规则。 ｜ 前置：无。

先按症状查对应条目，再核对代码与当前测试。下文数字属于记录中的历史批次，不应当作当前版本的质量结论。

## A. 蒸馏与统计口径

**A1. 长度目标被读成「每句」**
症状：注入正文写「N 字上下、一到两句」，模型每句都写满，总长翻倍。
原因：模型把字数预算理解成单句上限。
约束：写成「**两句合计** N 字（不要每句都写满）」。预算的作用域必须显式。

**A2. 空回答抬高了中位**
症状：某角色输出中位字长看起来正常，读回复发现一半是空字符串。
原因：`profile_from_texts` 剔除沉默回合，空回答不进长度分布。
约束：看分布指标前先看空回答比例与同格互异率。分布指标只描述「说了话的那些回合」。

**A3. 比值型指标进了复合分**
症状：13 个场景里有 7 个蒸馏分被压成 0.000，场景之间失去区分度。
原因：锚点密度是 hits/chars，短句场景的分母极小，基线在 0.19~3.48 之间跳，模型输出稳定在 4.0~4.4，偏离顶到上限，变成恒定惩罚。
约束：分母不稳的比值只做诊断列。进复合分的量必须在场景之间有稳定区分度。

**A4. 参照系必须是同角色同场景**
症状：用角色全局中位数约束，某些场景怎么改都不贴合。
原因：同一角色在不同场景的长度差 1.6~2.6 倍，全局数字在短场景过宽、长场景过严。
约束：评分与写 prompt 都用 `角色|场景` 级基线（130 个组合）。没有该组合时显式回退到全局，并在报告里标出来。

## B. 写进 prompt 的文本

**B1. 例句被整句照抄**
症状：生产臂 22%~27% 的回复逐字复述注入正文里的句子，最长公共子串 22 字。
原因：模型把「形态示例」当成「台词库」。
约束：注入正文不许出现可整句照抄的例句。只给字数上限、句数、结构描述、口癖长度的起手（≤4 字）。canon 原话改成「从你自己的档案里取」。这条的代价是长度贴合度从 0.512 掉到 0.461（旧批次记录，产物未随仓库发布），代价是自愿接受的。

**B2. 元叙述混进角色可见文本**
症状：注入正文出现「原作中位 6 字」，模型有概率顺着这个思路谈论自己的设定。
原因：写 prompt 的人在用分析语言思考，顺手把分析词汇写进了正文。
约束：角色可见文本里不许出现语料/实测/中位/p90/基线/lift/频次/统计这类词。门禁 `voice_meta_gate.py` 扫四个面：canon、voice manifest、说话尺度块、turn_logic 渲染结果。

**B3. 门禁的盲区比门禁的规则更要命**
症状：说话尺度块的标题写着「实测台词基线」，「实测」就在禁词表里，却一直没人发现。
原因：门禁只扫 `voice.py`，说话尺度块不在扫描范围内。
约束：门禁的价值等于它的扫描范围。新增一层 prompt 文本，就要同时扩门禁的覆盖面。

**B4. 过度矫正会造出另一种失真**
症状：为了禁止复述对方的话，立希的输出退化成「哈？」「哪句。」重复五次。
原因：约束只写了「不要做什么」，没有覆盖「该做什么照样要做」，模型用最短的安全回答规避风险。
约束：每条禁令都要配一条正例边界。评测时看同格互异率，重复度上升说明模型在躲。

## C. 评测方法

**C1. 单臂样本量的摆动大于效应**
症状：同一场景、同一个 prompt，乐奈的蒸馏分从 0.551 摆到 0.350。
原因：逐格 6 条时中位数的抽样噪声就是这样大。
约束：单臂逐格对比只当线索。下结论要池化多臂。`power_calc.py` 里记着实测：单条标准差 0.382，96 条/臂只够把区间压到 ±7.5 个百分点。

**C2. 长度偏差只用来找嫌疑**
症状：按长度偏差压灯的回复，压掉了她的 12 点省略号。
原因：省略号计入字数，而它对灯是内容不是赘余。
约束：长度与句数偏差负责把场景挑出来，判定必须读回复。「这条偏长」不是结论，「这条偏长是因为把对方的话补完整了」才是。

**C3. 夹具不可测时分数没有意义**
症状：某个场景反复得低分，改 prompt 也没用。
原因：「你刚才那句什么意思」需要上文有可指代的一句话，占位夹具没有上文。
约束：夹具要满足「有可指代的上文」和「system 段完整」两个条件。不满足时把该场景从结论里排除，并在文档里写明。

**C4. 时间是不可控变量**
症状：不同批次跑同一套夹具，数字对不上。
原因：角色对时段敏感（犯困、深夜场景），真实时钟把「几点」变成了隐藏变量。
约束：评测统一走 `tools/mock_clock.py`，默认固定白天。真实时钟下跑出来的数字不能与 mock 批次比较。

**C5. 参照物有两套口径时要说清用哪套**
症状：同一场景在两种参照口径下结论相反。
原因：一套是向量检索出的近邻台词，一套是场景反应词典的子集，前者更宽后者更贴题。
约束：报告里同时列出两套口径与各自条数。别只报对自己有利的那一套。

**C6. 只测「听话」的指标证明不了「像」**
症状：纯助手腔 fidelity 84.9、distill 0.606，高于真像角色的样本（82.0 / 0.286）——外部评审用仓库自己的评分函数跑构造样本复现，且药方 `composite_score` 早已写好却零调用。
原因：注入给模型的目标（说话尺度三数字）与评分维度同源，分数高只说明模型照做了长度指令；唯一带内容信号的维度又没进复合分。
约束：头号指标必须同时含风格与内容（composite = 风格 0.65 + 锚点 0.35）；「指标能分出助手腔」要有契约测试盯（`tests/test_eval_gates.py`）；写好的评分函数不接线等于没写。

**C7. 切了 holdout 就要有人读**
症状：语料按 hash 切了 20% 作 holdout，设计写明「验收用 holdout」，但所有下游只读 train——所有分数都是 in-sample 拟合度。
原因：切分机制建完后没人写消费端。
约束：验收轮必须跑 `scene_char_baseline.py --split holdout` + `scene_distill.py --baseline …_holdout.json`（`docs/04-evaluation.md` 第 10 节）；拿 holdout 数字回调 prompt 等于把留出集变回训练集。

**C8. 库 API 的「便利默认」会静默重演已修好的病**
症状：composite_score 的 anchor_ref 兜底（gold 字段 / 1.0）在画像字段移除后恒为 1.0；外部评审照库 API 默认调用，纯助手腔的 composite 重回榜首（90.2 > 89.9），全程无告警。
原因：生产路径显式传值修对了，库 API 的默认路径留在旧世界——而「静默失效比报错危险」。
约束：会改变排序语义的参数不给静默兜底，缺省即 `ValueError` 并在报错信息里指路正确来源。同理，被修复的病灶要在契约测试里钉「反向样本不得再赢」（`test_eval_gates.py`）。

**C9. 小计数指标的百分比门槛：稀释与噪声极值二选一**
症状：锚点密度门槛先被「跨角色均值」稀释（素世 −25% 只动均值 −3.4%，漏检）；改成「逐角色取最差」后空比较误报率 ~95%（每角色 hits 只有 2~19 次，爱音 2 次 → 标准误 71%）。合成测试两版都「通过」，因为合成数据没有噪声。
原因：密度 = hits/chars 是小整数计数的比值，不是连续精确量；新指标上线前没做功效核算（`power_calc.py` 就在仓库里）。
约束：计数型指标按**计数**做检验（合并泊松精确检验），不用固定百分比；打印可检测下限，样本不够就照实说「无结论」（docs/00 §4.4）；逐角色小计数数字只能当诊断列，不参与判定。

## D. 工程与流程

**D1. 静默失效比报错危险**
症状：探针跑了 105 条，评分为低，读回复发现模型在写通用助手腔。
原因：`--assemble` 装好的 system 被下一行 `msgs[0]["content"] = patched_sys` 原地覆盖，占位夹具的 system 本就是空字符串。
约束：同一个目标的多来源赋值只能有一个生效（if / elif / else）。关键装配结果加下限守卫：system 短于 1000 字符直接报错退出。

**D2. 门禁必须覆盖它要守的那条路径**
症状：prompt diff 门禁跑绿，而目标改动没被看到。
原因：真实运行时那条 dump 路径在开发者模式下按设计不触发 turn_logic，改动恰好在该路径上。
约束：门禁要验证的是**目标路径**，不是任意一条路径。看到「跑绿」先问它扫了什么。

**D3. before 臂不能事后补造**
症状：改动完成后才想起来要对比。
原因：流程上没有先留基线。
约束：改动前先跑 `dump_prompt.py --phase before`，两臂由同一脚本、同一输入、同一时钟产出。改完之后从同一 checkout 补造的 before 不算证据。

**D4. 工具在正确使用时不该退出非零**
症状：`dump_turn_logic_gate.py --phase before` 退出 1，因为它把「什么都不触发」判成失败。
原因：判定表只对 after 臂成立，before 臂本来就该全空。
约束：基线臂只产基线，不判期望。工具的退出码要能被 CI 直接使用。

**D5. 独立发布后才发现依赖现场计算**
症状：仓库 clone 下来跑探针，第一步就崩。
原因：评分的 gold 画像每次从语料现场计算，而语料不随仓库发布。
约束：让发布物自洽。把聚合量导出为 `data/style_profiles.json`（只有均值、标准差、分位、出现率），探针在无语料时读它，并在启动日志里打印画像来源。

**D6. 无损与有损的边界**
症状：为了让后处理更强，把「去掉冗余起手」塞进清洗函数，破坏了「切分/清洗无损」的契约。
原因：清洗与风格改写的目标不同，前者保证不丢字，后者会删字。
约束：无损清洗留在 `clean_reply`，会删字的风格改写放在 API 层，并有独立开关。两者不混。

**D7. 没有 argparse 的脚本，`--help` 也会真的动手**
症状：给全仓库脚本跑一遍 `--help` 做冒烟检查，外部语料目录被覆盖成 0 字节，退出码是 0。
原因：`build_gold.py` 没有 argparse，`--help` 被当成普通参数忽略，合并照跑；它的源文件按脚本自身目录解析（在新仓库里不存在 → 0 条），而输出目录来自 `IDIOLECT_CORPUS_DIR`（指向外部）。
约束：会写数据的脚本一律 argparse；读语料前 `require_corpus()` 检查非空；写之前判零结果并拒绝（除非显式 `--force-empty`）。`offline_smoke.py` 的「工具.CLI 安全」项守着这三条。

**D8. 同一份输入两次跑出不同结果，等于没有发布数据**
症状：`data/scene_stats.json` 里同一个场景的词表，两次运行不同；「发布数据能否重建」说不清。
原因：`logodds_signature` 从 `set` 迭代取词，排序只按 logodds；同为 2.48 的两个词谁进 top-N 取决于字符串哈希随机化。
约束：进 prompt 或进发布数据的排序都要有兜底键（并列按词排）。判定标准不是「看起来一样」，而是**两个独立进程的输出逐字节相同**。

## E. 改法上的元规则

**E1. 具名锚点优先于通用规则**
症状：按一条通用规则（某句口头禅属于另一个角色）从 canon 里删掉了「有趣的女人」，而这句话是爱音对乐奈的最高评价。
原因：通用规则丢掉了「谁对谁说」的信息。
约束：改 canon 之前先读角色档案里关于该对象的具名段落。规则与具名锚点冲突时，以具名锚点为准。

**E2. 先读再改**
症状：改了三次才发现要改的东西在另一个模块。
原因：凭印象定位。
约束：动手前读目标文件与相邻文档。项目里的 `docs/`、`tests/` 与脚本头部的注释记录了上一轮的结论，重复踩坑通常是因为没读。

**E3. 分数不是结论**
症状：分数涨了，角色却更难读。
原因：指标能被「变冷淡」「变短」刷出来。
约束：每轮改完至少读 6 条回复，并把它们与原作同场景台词并排看（`scene_feedback.py`）。分数负责筛选嫌疑，人负责下结论。

**E4. 约束之间会互相吞掉**
症状：为 A 场景加的禁令让 B 场景崩了。
原因：prompt 是一个共享预算，全局约束对每个场景生效。
约束：加约束后跑全套场景矩阵，比较各场景的 excess。某个场景大幅改善而另一个大幅恶化时，说明约束写得太宽。

## F. 发布前的自查

写完一个要给别人用的仓库，除了功能还要过一遍这四条。它们都是从实际事故里长出来的。

1. **每个脚本都要 `--help` 安全。** 逐个跑 `--help` 抓 import 与语法错误，顺手暴露「跑起来就干活」的脚本。`offline_smoke.py` 的「工具.CLI 安全」项把这条变成静态检查。
2. **写数据前先判零结果。** 空结果通常意味着上游缺文件，写下去就是把已有的好数据覆盖掉。`build_gold.py` 拒绝写出 0 条，除非显式 `--force-empty`。
3. **发布形态要由命令产出，不能靠人工编辑。** 「剥掉例句字段」原本是临时脚本里的一步，于是「`data/` 是怎么来的」无法从仓库复现；现在它是 `--no-exemplars`。
4. **克隆到空目录再跑一遍。** 本地跑通不代表发布出去能跑：绝对路径、缺失的配置文件、隐式的工作目录依赖，都只有在干净克隆里才暴露。验证方式是 `git clone` 到临时目录后跑 `pytest`、`offline_smoke` 与探针 dry-run。
5. **打包产物要打开看，不能只看「装上了」。** `pip install .` 报成功、`python -m idiolect list` 也能跑，但 wheel 里其实没有 `idiolect/characters/**`——因为 `namespaces = false` 下缺 `__init__.py` 的目录不算包。要验证安装，得在**干净 venv** 里跑一条依赖角色包的命令（如 `python -m idiolect sizes`），并直接列 wheel 内容。

## G. 评测链路自己的坑（v0.1.2）

这一组来自 grounding 评测的建设过程：评测代码本身也会静默失效，而且失效时看起来就像「全部通过」。

**G1. 接收参数却丢弃它的门禁**
症状：一个比较「有隐藏信息 / 无隐藏信息」两侧 messages 的门禁永远 PASS。
原因：隐藏参数作为可选参数传进去，函数从不读它，两侧其实由同一份输入构建；相等由签名保证，不由行为保证。
约束：每次评测自带金丝雀——已知违规必须让检查器翻转判决；`idiolect selftest` 的 M20 专门注入这种形状。检出靠行为，不靠签名（M19 的等价体反过来约束：只换 wrapper 不得被判差异）。

**G2. 归一化之前就切了小句**
症状：`1,200` 匹配不到 `1200`，`东侧……入口` 匹配不到 `东侧入口`，而归一化函数单测全绿。
原因：主张匹配先按标点切小句再归一化；逗号与省略号把一个值切成了两半，归一化根本没机会处理。
约束：表示算子必须在**完整的匹配路径**上逐个认证（`matching.certify_operators()` 的成对探针），不能只测归一化函数本身。这条是算子认证第一次跑就抓到的。

**G3. ID 允许冒号，解析器就不能按字符类贪婪截取**
症状：所有 current 条目都被判「关键证据不在 messages 里」，history 条目却正常。
原因：渲染形状是 `- evidence_17: 正文`，而 ID 的字符类包含 `:`，贪婪匹配把 `evidence_17:` 整个当成了 ID；history 行后面跟的是空格，碰巧没事。
约束：解析渲染结果时按「第一个 `: ` 或 ` [`」截断；端到端跑一遍内置健康回放，PASS 才算解析器可用。

**G4. 计量把占位行当成证据**
症状：关键证据放在末尾，计量说它在 98.9% 的位置。
原因：空桶渲染成 `- （无）`，计量按 `- ` 前缀数行，把占位行也算进去了。
约束：计量与 prompt 边界检查共用同一个证据块解析器（`grounding.parse_evidence_block`），不各写一份。

**G5. 宽泛的批量替换会改到别的函数**
症状：为了消除一个未使用变量，用正则删掉了 `cat_data = X.get(cat, {})`，结果另一个函数里同名、仍在使用的定义也被删了。
原因：替换按文本形状匹配，不按位置；同名模式在文件里出现多次。
约束：清理 lint 时只改 linter 报告的那一行（按行号断言原文再删）；改完立刻跑 `ruff check --select F821` 与 prompt dump 对比——这次就是 F821 当场抓到的。

**G6. 评分环境不同，数字就不可比**
症状：同一批回复，仓库里跑与 wheel 环境里跑的风格轴结果不同。
原因：句数、越界、canon 事实检查依赖仓库 `tools/`，wheel 环境里没有。
约束：缺失的评分模块判 `not_applicable` 并在门禁说明里列出（不算通过）；manifest 记录本次实际跑了哪些检查，两种环境的批次不会被自动比较。
